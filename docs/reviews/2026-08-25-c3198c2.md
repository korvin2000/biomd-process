## Blocking — fixed

### 1. The circuit breaker could no longer open · `src/llm/LlmGateway.ts`

```ts
if (countsTowardCircuit(failure.kind)) this.breakers.recordFailure(target.key);
else this.breakers.recordSuccess(target.key);   // ← removed
```

Not counting a request-scoped failure is right. Recording a **success** is not:
`CircuitBreakerRegistry.recordSuccess` is `entries.delete(key)` — a full state wipe.

| Scenario (threshold 3) | Before the fix | After |
|---|---|---|
| 100/100 requests fail `unknown` | breaker `closed` | `open` (…`unknown` still does not count; a target that *only* fails this way is reported by the fallback line) |
| 100/100 fail `response_format` | `closed` | `closed` — correct, the endpoint answers |
| `server`,`server`,`response_format`,`server` | `closed` — counter erased | `open` |
| open → cooldown → half-open probe fails `response_format` | **fully closed**, all traffic restored | stays open |

Fix: the `else` branch is gone. Only a real success clears the record.
Regression tests: `tests/reliability.test.ts` → *the circuit breaker under mixed failure kinds* (4).

The flipped assertion in `tests/progresslog.test.ts` (`TARGET DOWN … .toBe(true)` → `false`) was the
regression documented as intent — a green suite is not a review here.

### 2. `model_unavailable` wrote a target off for the whole run · `src/reliability/errors.ts`

`disablesTarget` included it, and `unavailableTargets` is never cleared. But the kind's own doc says
"Model unknown **or temporarily unavailable**", and `ErrorClassifier` maps **any 404** and
`no healthy deployment` to it. `docs/ref/failure-modes.md` records omniroute doing exactly that for a
model listed in its own `/v1/models`, *working again minutes later* — and the last time it did,
37 web searches went to the paid endpoint with no line saying so.

Live blast radius: the `websearch` pool is `[search-mx, search-std, search-safe, paid-search]`, and
this commit made `search-mx` and `search-std` the **same wire model**. One flaky window took both out
permanently, then `search-safe`, and `paid-search` served the rest of the corpus.

Fix: `disablesTarget` holds only `auth` and `quota`. The breaker still counts `model_unavailable`, so
a genuinely dead target opens and recovers on the cool-down.

### 3. `models --probe` billed on every invocation · `src/cli/commands/models.ts`

The probe began sending a live search at `maxOutputTokens: 512` to any `web_search` target —
including `paid-search` (`openai/gpt-5.6-luna:online`), where `:online` adds a per-request search fee.
`--probe` is documented as required before every real run.

Fix: search is verified on **free** targets only (all declared pricing rates zero). A paid search
target gets the plain completion and the row reads `search NOT verified (paid — use --probe-search)`;
the new `--probe-search` opts in explicitly. A dim line before the table names what was skipped.

### 4. An unresolved question was committed into the live config · `biomd.config.yaml`

`minimax-m3` carried `# I am not sure, what is a correct way to configure provider?` with **both**
forms set. The wire body confirms `params.extra.provider` is assigned after `body['provider']`, so
the raw escape hatch won and the typed block was dead.

Fix: the typed `provider:` block only, matching `deepseek` above it, with a comment recording why —
it is the only form offering `requireParameters`, the documented cure for a silently dropped sampler.

> `requireParameters` was **not** added: `providerRoutingSchema` says to turn it on for a target whose
> `params` carry something beyond `temperature`, and `minimax-m3` carries only `temperature`.

## High — fixed

**5. `requireVerifiedSource` piggybacked on `requireSource`.** One flag silently came to mean two
things, and the live config has `requireSource: true`. Comparison was exact equality on
`normalizeUrl`, so a trailing slash, `http` vs `https`, `www.` or `?utm_source=` rejected a citation
that *was* verified — costing the field, which is the same damage the check exists to prevent.
Fix: a separate `tasks.websearch.requireVerifiedSource` (default `true`), and a new `sourceKey()`
comparison key in `answer.ts` that drops scheme, `www.`, trailing slash, fragment and campaign
params. `normalizeUrl` is untouched — it still produces the URL written into a dossier.

**6. A truncated streamed Responses call reported zero tokens.** `collectResponsesStream` handled
`response.completed` and `response.failed` but not **`response.incomplete`** — the terminal event of a
call that hits `max_output_tokens`. Reproduced: a stream carrying `usage.total_tokens: 37768` and
`incomplete_details.reason: 'max_output_tokens'` returned `usage` undefined. So 37,768 tokens billed
as 0, invisible to the budget guard, and `finishReason: 'unknown'` instead of `'length'` — which
misroutes the truncation to the *retryable* `response_format`, buying the identical cut three times.
Fix: all three terminal events are collected.

**7. A CIRCUIT OPEN line masked a later TARGET DOWN.** Both announcements deduped on one per-target
set, so the recoverable notice consumed the one-shot slot. Fix: `announceCircuitOpen` with its own
set, and a real TARGET DOWN still prints after it.

**8. The docs contradicted the shipped config.** `failure-modes.md` claimed "the live configuration
records date conflicts" while `biomd.config.yaml` sets `onDateConflict: prefer-precise`, and
`upgradePrecision: true` carried a comment describing the `false` setting. Fix: the docs and comments
now state what the file actually does, and name the deviation from the schema default as a decision.
